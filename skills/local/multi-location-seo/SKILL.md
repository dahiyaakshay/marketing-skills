# Local: Multi-Location SEO

Structures SEO strategy and page architecture across a business with multiple physical locations — the core challenge is scaling location-specific relevance without duplicating content or diluting management effort.

**When invoking**: On first use, briefly note the duplicate-content risk below. On subsequent use, go straight to the strategy.

## Scope

Cross-location architecture and management strategy. For an individual location page, see **local-landing-page-builder**. For a single GBP listing, see **gbp-optimizer** — this skill governs doing that consistently across many.

## The Core Tension

Each location needs its own page for proximity-based relevance (Google's distance factor operates per search, meaning a business without a page/listing near a given searcher is structurally disadvantaged for that search regardless of overall brand strength) — but scaling location pages without genuine differentiation risks the templated, thin-content pattern described in **local-landing-page-builder**, which underperforms and can create the appearance of duplicate content across the domain.

## Structural Approach

| Element | Guidance |
|---|---|
| **URL structure** | Consistent, logical pattern (e.g. /locations/city-name/) rather than inconsistent structures across different locations added at different times |
| **Genuine per-location differentiation** | Real local team info, testimonials, and service nuances per **local-landing-page-builder** — this doesn't scale for free and requires actual content investment per location, not just a template |
| **Individual GBP listing per physical location** | Each physical location needs its own complete, accurately-categorized GBP profile — a shared or consolidated listing for multiple physical addresses works against Google's local ranking model |
| **Centralized NAP management** | A single source of truth for each location's NAP, feeding both the website and all directory citations (see **local-citation-audit**), to avoid drift as locations are added, closed, or moved |
| **Location expansion as a growth lever** | For businesses hitting a proximity ceiling in their current footprint, opening additional physical locations is sometimes the most effective way to expand local reach, since distance itself isn't optimizable at a fixed address |

## Workflow

1. Establish a consistent URL and page-template structure for location pages across the business.
2. Confirm each physical location has its own complete, correctly-categorized GBP listing.
3. Build genuine differentiation into each location page rather than a pure template swap (see **local-landing-page-builder**).
4. Centralize NAP data management so citation and schema updates propagate consistently (see **local-citation-audit**, **local-schema-markup**).
5. Periodically audit for stale listings from closed or moved locations.
6. Evaluate new-location expansion as a legitimate lever when growth is constrained by proximity in the current footprint.
